# Partition reassignment and leader election

## Objective

Move the replicas and the leaders of a topic between brokers with [`playground topic reassign`](https://kafka-docker-playground.io/#/playground%20topic%20reassign) (wraps `kafka-reassign-partitions`) and [`playground topic elect-leader`](https://kafka-docker-playground.io/#/playground%20topic%20elect-leader) (wraps `kafka-leader-election`), to reproduce what a client sees during a rebalance or a leader change, without stopping a broker.

## How to run

```bash
playground run -f topic-reassign-and-leader-election<tab>
```

## What the script does

It starts the plaintext environment with 3 brokers (ids 1, 2 and 3, like `--enable-multiple-brokers`), creates topic `orders` (3 partitions, replication factor 2) and produces 1000 records of 10 KB, then:

1. moves every partition to brokers 2 and 3 with a 1 MB/s replication throttle: `topic reassign --topic orders --replicas 2,3 --throttle 1000000` (waits until the reassignment is completed, which also removes the throttle)
2. spreads the partitions over the 3 brokers again, with a plan generated by `kafka-reassign-partitions --generate`: `topic reassign --topic orders --brokers 1,2,3`
3. elects the preferred leaders: `topic elect-leader --topic orders`
4. moves the leader of partition 0 to its other replica: `topic elect-leader --topic orders --partition 0 --leader <broker>`
5. checks that the 1000 records can still be consumed

Each step checks the replicas and leaders with `playground topic describe`.

## Use it in a repro

While a client or a connector runs:

```bash
# a slow reassignment: under-replicated partitions for a while
playground topic reassign --topic orders --replicas 1,3 --throttle 100000 --no-wait
playground topic reassign --topic orders --verify-only

# a leader change (NOT_LEADER_OR_FOLLOWER, metadata refresh on the client)
playground topic elect-leader --topic orders --partition 0 --leader 3
```
