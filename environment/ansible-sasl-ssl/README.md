# cp-ansible with SASL_SSL

## Description

The [ansible](../ansible/) environment (Confluent Platform deployed by the cp-ansible playbooks in systemd containers),
with security enabled by the inventory:

```yaml
all:
  vars:
    sasl_protocol: plain
    ssl_enabled: true
```

- SASL/PLAIN authentication and SSL encryption on every listener of the brokers (the users of cp-ansible:
  `admin`, `kafka_connect`, `schema_registry`…)
- https on the REST APIs of Schema Registry, Connect, ksqlDB and REST Proxy
- certificates generated by cp-ansible (self-signed CA, one keystore and truststore per host in `/var/ssl/private/`)

## How to run

```bash
playground start-environment --environment ansible-sasl-ssl
playground run -f connect/connect-http-sink/http_no_auth.sh --environment ansible-sasl-ssl
```

Everything else (versions, `--enable-*` flags, translation of the example's override, running the playbook again) is
the same as in [ansible](../ansible/README.md).

## How the playground commands get the security

Nothing is hard-coded: after the playbook, `environment/ansible/start.sh` reads what cp-ansible rendered.

| What | From |
| --- | --- |
| `/etc/kafka/client.properties` of each host, used by the Kafka tools of the playground commands | the `client.properties` cp-ansible writes on the brokers, else the client settings of the component (connect worker, `kafkastore.*` of Schema Registry, ksqlDB server, `client.*` of REST Proxy) |
| `environment/ansible/inventory/ca.pem`, for the https REST APIs | the certificates of the truststore of `connect` |
| https or http for Connect, Schema Registry, ksqlDB | the `listeners=` of their properties files |

The certificates are issued for the host names (`connect`, `schema-registry`…), not `localhost`: the REST calls use
`https://connect:8083` with `curl --cacert environment/ansible/inventory/ca.pem --resolve connect:8083:127.0.0.1`.

`playground connector create-or-update` adds to the connector config the security of the connect worker for the
connector's own Kafka clients (`confluent.topic.*`, `redo.log.consumer.*`, the history producers and consumers of
Debezium, `reporter.*`), and switches the converters to `https://schema-registry:8081` with the truststore of the worker.
