==========================
Exactly Once Support
==========================
🔘 exactly.once.support

Permitted values are requested, required. If set to "required", forces a preflight check for the connector to ensure that it can provide exactly-once semantics with the given configuration. Some connectors may be capable of providing exactly-once semantics but not signal to Connect that they support this; in that case, documentation for the connector should be consulted carefully before creating it, and the value for this property should be set to "requested". Additionally, if the value is set to "required" but the worker that performs preflight validation does not have exactly-once support enabled for source connectors, requests to create or validate the connector will fail.

	 - Type: STRING
	 - Default: requested
	 - Importance: MEDIUM
	 - Required: false

🔘 transaction.boundary

Permitted values are: poll, interval, connector. If set to 'poll', a new producer transaction will be started and committed for every batch of records that each task from this connector provides to Connect. If set to 'connector', relies on connector-defined transaction boundaries; note that not all connectors are capable of defining their own transaction boundaries, and in that case, attempts to instantiate a connector with this value will fail. Finally, if set to 'interval', commits transactions only after a user-defined time interval has passed.

	 - Type: STRING
	 - Default: poll
	 - Importance: MEDIUM
	 - Required: false

🔘 transaction.boundary.interval.ms

If 'transaction.boundary' is set to 'interval', determines the interval for producer transaction commits by connector tasks. If unset, defaults to the value of the worker-level 'offset.flush.interval.ms' property. It has no effect if a different transaction.boundary is specified.

	 - Type: LONG
	 - Default: null
	 - Importance: LOW
	 - Required: false

🔘 task.parallel.transform.enabled

If true, transform and convert operations for this source task run on a per-task thread pool instead of on the task thread. Producer.send() remains sequential to preserve ordering. REQUIREMENT: every SMT and converter configured on the task must be thread-safe — they will be invoked concurrently from multiple worker threads on disjoint records. Leave disabled for connectors whose transforms or converters hold mutable per-instance state without synchronization. Disabled by default.

	 - Type: BOOLEAN
	 - Default: false
	 - Importance: LOW
	 - Required: false

🔘 task.parallel.transform.threads

Number of threads in the per-task pool used when task.parallel.transform.enabled is true. Bounded to [1, 3] to prevent any single task from monopolizing CPU.

	 - Type: INT
	 - Default: 2
	 - Importance: LOW
	 - Required: false

🔘 task.parallel.transform.chunk.size

Number of records processed per parallel chunk when task.parallel.transform.enabled is true. Caps in-flight memory: peak extra heap per chunk ≈ chunkSize × 2 × avg_record_size. Tune down for connectors shipping records larger than 20 KB. Bounded to [100, 50000].

	 - Type: INT
	 - Default: 10000
	 - Importance: LOW
	 - Required: false

Firebase
==========================
🔘 gcp.firebase.database.reference

The firebase database reference from which the connector will read records

	 - Type: STRING
	 - Default: null
	 - Importance: HIGH
	 - Required: true

🔘 gcp.firebase.credentials.path



	 - Type: false
	 - Default: STRING
	 - Importance: Path to the GCP private key file,this file is needed for service account authentication.
	 - Required: HIGH

🔘 gcp.firebase.credentials.json

The contents of the JSON service key file. If empty, credentials are read from the gcp.firebase.credentials.path configuration.

	 - Type: PASSWORD
	 - Default: null
	 - Importance: HIGH
	 - Required: false

🔘 gcp.firebase.snapshot

If true, the connector performs a snapshot once and listen to further changes. A complete snapshot is taken each time the connector restarts when the configuration gcp.firebase.snapshot is set to true, this may lead to connector writing duplicate records to Kafka topic. If false, the connector skips the initial database snapshot and listens to changes and writes them to kafka topic.

	 - Type: BOOLEAN
	 - Default: false
	 - Importance: HIGH
	 - Required: false
