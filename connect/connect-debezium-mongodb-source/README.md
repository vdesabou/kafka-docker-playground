# Debezium MongoDB source connector

## Objective

Quickly test the [Debezium MongoDB](https://debezium.io/documentation/reference/stable/connectors/mongodb.html) connector.

## Prerequisites

With CP 8.x, the minimal supported connector version is `2.5.0` (the script exits with code 111 otherwise).

## How to run

```bash
playground run -f debezium-mongodb-source.sh
```

| Script | Description |
| --- | --- |
| `debezium-mongodb-source.sh` | Basic example capturing collection `inventory.customers` |
| `debezium-mongodb-source-ssl.sh` | MongoDB with TLS (self-signed certificate generated by the script, connector uses a JKS truststore) |
| `debezium-mongodb-source-incremental-snapshot.sh` | Ad hoc incremental snapshot of a newly added collection, triggered through the signal collection `inventory.debezium_signal` |
| `debezium-mongodb-source-incremental-snapshot-kafka-signal.sh` | Same, triggered through the Kafka signal topic `dbz-signals` |

The mongo-express UI is available at [http://localhost:18081/](http://localhost:18081/) (not in the SSL example).

## What the script does

1. Starts the environment with a MongoDB container, initializes replica set `debezium` (the member host must be `mongodb:27017`) and creates user `debezium`.
2. Inserts a record in collection `inventory.customers`.
3. Creates the `debezium-mongodb-source` connector (`io.debezium.connector.mongodb.MongoDbConnector`, `topic.prefix` `dbserver1`).
4. Verifies that topic `dbserver1.inventory.customers` contains the record with `playground topic consume`.

The incremental snapshot variants then:

1. Insert a record in a new collection `inventory.customers2` and update the connector to include it.
2. Insert another record: only this new record shows up in `dbserver1.inventory.customers2`.
3. Trigger an `execute-snapshot` (`incremental`) signal, either by inserting a document in `inventory.debezium_signal` or by producing to topic `dbz-signals` with `playground topic produce`.
4. Verify that `dbserver1.inventory.customers2` now contains all records.

The SSL variant generates a self-signed certificate and a JKS truststore under `ssl/`, starts MongoDB with TLS and sets `mongodb.ssl.enabled=true` with `mongodb.ssl.truststore` in the connector.

## Benchmark

[`benchmark-load.bash`](benchmark-load.bash) inserts documents in the `inventory.customers` collection of the examples (or the first collection of `collection.include.list`) for [`playground connector benchmark`](https://kafka-docker-playground.io/#/playground%20connector%20benchmark), with `mongosh` in the `mongodb` container (with the TLS options of the SSL variant). The documents have the shape of an existing one. Once one of the examples is running:

```bash
# insertMany of 100000 documents
playground connector benchmark --nb-records 100000

# 5000 insertOne
playground connector benchmark --nb-records 5000 --shape small-txn

# updates of 10000 existing documents (run a bulk load first)
playground connector benchmark --nb-records 10000 --shape update

# throughput and end-to-end latency (kafka timestamp - source.ts_ms, the commit time) during 2 minutes while batches of 10000 documents are inserted
playground connector benchmark --mode steady --duration 2m --nb-records 10000
```
