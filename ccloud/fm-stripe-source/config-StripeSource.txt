==========================
Kafka Cluster credentials
==========================
🔘 kafka.auth.mode

Kafka Authentication mode. It can be one of KAFKA_API_KEY or SERVICE_ACCOUNT. It defaults to KAFKA_API_KEY mode, whenever possible.

	 - Type: STRING
	 - Default: ${connect.regional.connector}
	 - Importance: HIGH
	 - Required: false

🔘 kafka.service.account.id

The Service Account that will be used to generate the API keys to communicate with Kafka Cluster.

	 - Type: STRING
	 - Default: 
	 - Importance: HIGH
	 - Required: false

🔘 kafka.api.key

Kafka API Key. Required when kafka.auth.mode==KAFKA_API_KEY.

	 - Type: PASSWORD
	 - Default: 
	 - Importance: HIGH
	 - Required: false

🔘 kafka.api.secret

Secret associated with Kafka API key. Required when kafka.auth.mode==KAFKA_API_KEY.

	 - Type: PASSWORD
	 - Default: 
	 - Importance: HIGH
	 - Required: false

🔘 datapreview.schemas.enable

This config key only applies to data preview requests and governs whether the data preview output has record schema with it.
The visibility condition is set such that it can never be true.
So this key does not show in create connector UI.

	 - Type: STRING
	 - Default: false
	 - Importance: LOW
	 - Required: false

==========================
Schema Config
==========================
🔘 schema.context.name

Add a schema context name. A schema context represents an independent scope in Schema Registry. It is a separate sub-schema tied to topics in different Kafka clusters that share the same Schema Registry instance. If not used, the connector uses the default schema configured for Schema Registry in your Confluent Cloud environment.

	 - Type: STRING
	 - Default: default
	 - Importance: MEDIUM
	 - Required: false

==========================
Output messages
==========================
🔘 output.data.format

Output Kafka record value format: AVRO, JSON_SR, or PROTOBUF, each with Confluent Cloud Schema Registry. With PROTOBUF, set Schema evolution mode to NONE.

	 - Type: STRING
	 - Default: JSON_SR
	 - Importance: HIGH
	 - Required: true

🔘 schema.enforce

How the connector handles a field that Stripe returns but the connector doesn't know. EVOLVE adds it to the topic's schema once, with its detected type. NONE adds it as an optional string, only in the records that carry it. With PROTOBUF, use NONE.

	 - Type: STRING
	 - Default: EVOLVE
	 - Importance: MEDIUM
	 - Required: true

==========================
Authentication
==========================
🔘 stripe.api.key

Your Stripe secret key or restricted key. We recommend a restricted key with Read access to the resources you select and to Events. A sandbox key reads sandbox data, and a live mode key reads live data.

	 - Type: PASSWORD
	 - Default: 
	 - Importance: HIGH
	 - Required: true

🔘 stripe.connected.account.id

Leave blank to read your own Stripe account, or enter a connected account ID, such as acct_1Nv0FGQ9RKHgCVdK, to read that account instead. Each connector reads one account, so create one connector per connected account.

	 - Type: STRING
	 - Default: 
	 - Importance: MEDIUM
	 - Required: false

==========================
Stripe resources
==========================
🔘 stripe.resources

The Stripe resources to sync, up to 7 per connector. To sync more, create another connector.

	 - Type: LIST
	 - Default: 
	 - Importance: HIGH
	 - Required: true

🔘 topic.prefix

Prefix for the Kafka topics of every selected resource. With the default, Charges are written to stripe-charges and their changes to stripe-charges_events.

	 - Type: STRING
	 - Default: stripe-
	 - Importance: MEDIUM
	 - Required: true

🔘 stripe.initial.start.timestamp

Load records created at or after this time, as a Unix timestamp in seconds. 0 loads all history. Stripe keeps change events for 30 days, so older changes are not loaded.

	 - Type: STRING
	 - Default: 0
	 - Importance: HIGH
	 - Required: true

==========================
Polling configurations
==========================
🔘 poll.interval.ms

How long, in milliseconds, the connector waits between requests to Stripe for each resource. This also sets how fast history loads, one page of up to ``100`` records per interval. Lower values load history faster and deliver changes sooner, but use more of your Stripe API rate limit and read allocation.

	 - Type: INT
	 - Default: 10000
	 - Importance: MEDIUM
	 - Required: true

==========================
Reporter
==========================
🔘 reporter.error.topic.name

The name of the topic to produce errant records after each unsuccessful API operation. Defaults to 'error-${connector}' if not set. You can provide ``${connector}`` in the value to use it as a placeholder for the logical cluster ID.

	 - Type: STRING
	 - Default: error-${connector}
	 - Importance: LOW
	 - Required: false

🔘 errors.tolerance

Use this property if you would like to configure the connector's error handling behavior. WARNING: This property should be used with CAUTION for SOURCE CONNECTORS as it may lead to dataloss. If you set this property to 'all', the connector will not fail on errant records, but will instead log them (and send to DLQ for Sink Connectors) and continue processing. If you set this property to 'none', the connector task will fail on errant records.
