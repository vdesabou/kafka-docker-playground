==========================
How should we connect to your data?
==========================
🔘 connector.class



	 - Type: STRING
	 - Default: 
	 - Importance: HIGH
	 - Required: true

🔘 name

Sets a name for your connector.

	 - Type: STRING
	 - Default: 
	 - Importance: HIGH
	 - Required: true

==========================
Kafka Cluster credentials
==========================
🔘 kafka.auth.mode

Kafka Authentication mode. It can be one of KAFKA_API_KEY or SERVICE_ACCOUNT. It defaults to KAFKA_API_KEY mode, whenever possible.

	 - Type: STRING
	 - Default: ${connect.regional.connector}
	 - Importance: HIGH
	 - Required: false

🔘 kafka.service.account.id

The Service Account that will be used to generate the API keys to communicate with Kafka Cluster.

	 - Type: STRING
	 - Default: 
	 - Importance: HIGH
	 - Required: false

🔘 kafka.api.key

Kafka API Key. Required when kafka.auth.mode==KAFKA_API_KEY.

	 - Type: PASSWORD
	 - Default: 
	 - Importance: HIGH
	 - Required: false

🔘 kafka.api.secret

Secret associated with Kafka API key. Required when kafka.auth.mode==KAFKA_API_KEY.

	 - Type: PASSWORD
	 - Default: 
	 - Importance: HIGH
	 - Required: false

🔘 datapreview.schemas.enable

This config key only applies to data preview requests and governs whether the data preview output has record schema with it.
The visibility condition is set such that it can never be true.
So this key does not show in create connector UI.

	 - Type: STRING
	 - Default: false
	 - Importance: LOW
	 - Required: false

==========================
Schema Config
==========================
🔘 schema.context.name

Add a schema context name. A schema context represents an independent scope in Schema Registry. It is a separate sub-schema tied to topics in different Kafka clusters that share the same Schema Registry instance. If not used, the connector uses the default schema configured for Schema Registry in your Confluent Cloud environment.

	 - Type: STRING
	 - Default: default
	 - Importance: MEDIUM
	 - Required: false

==========================
Output messages
==========================
🔘 output.data.format

Output Kafka record value format. Only ``JSON`` is supported. If Dynamics 365 adds a column after the connector starts, the connector picks it up automatically.

	 - Type: STRING
	 - Default: JSON
	 - Importance: HIGH
	 - Required: true

==========================
Authentication
==========================
🔘 dynamics365.url

The URL of the Dynamics 365 (Dataverse) environment to read data from. For example: ``https://myorg.crm.dynamics.com``. Find it in the [Power Platform admin center](https://admin.powerplatform.microsoft.com/environments) under Environments.

	 - Type: STRING
	 - Default: 
	 - Importance: HIGH
	 - Required: true

🔘 oauth2.token.url

The Microsoft Entra ID endpoint for fetching the OAuth2 token. For example: ``https://login.microsoftonline.com/{tenant-id}/oauth2/v2.0/token``. To register the app and find its token endpoint, see Microsoft's [app registration quickstart](https://learn.microsoft.com/entra/identity-platform/quickstart-register-app). Supported grant type is ``client_credentials``.

	 - Type: STRING
	 - Default: 
	 - Importance: HIGH
	 - Required: true

🔘 oauth2.client.id

The application (client) ID of the Microsoft Entra app registration used by the connector, displayed on the Overview page as a GUID. Link the app registration to a Dynamics 365 Application User with read access to the selected entities. For details, see Microsoft's guide on [server-to-server authentication](https://learn.microsoft.com/power-apps/developer/data-platform/use-single-tenant-server-server-authentication).

	 - Type: STRING
	 - Default: 
	 - Importance: HIGH
	 - Required: true

🔘 oauth2.client.secret

The client secret of the Microsoft Entra app registration. Use the secret ``Value`` from Certificates & secrets, not the ``Secret ID``, and copy it when created because it is shown only once. Client secrets expire, so the connector fails to authenticate after the secret lapses.

	 - Type: PASSWORD
	 - Default: 
	 - Importance: HIGH
	 - Required: true

==========================
Entities
==========================
🔘 entities.num

The number of Dynamics 365 entities to fetch data from.

	 - Type: INT
	 - Default: 1
	 - Importance: HIGH
	 - Required: true

🔘 dynamics365.topic.prefix

Prefix added to the start of every topic name. The topic name is ``{prefix}{entity}`` with nothing in between, so prefix ``crm`` and entity ``accounts`` give the topic ``crmaccounts``.

	 - Type: STRING
	 - Default: 
	 - Importance: HIGH
	 - Required: true

==========================
Polling configurations
==========================
🔘 poll.interval.ms

How often, in milliseconds, the connector polls Dynamics 365 for new or changed records. Applies to every entity. Lower values mean fresher data but more requests against Dynamics 365 service protection limits.

	 - Type: INT
	 - Default: 1000
	 - Importance: MEDIUM
	 - Required: true

🔘 page.size

The number of records the connector requests per API call, applied to every entity. Valid range is ``1`` to ``5000`` — Dynamics 365 silently caps anything higher at ``5000``.

	 - Type: INT
	 - Default: 2500
	 - Importance: MEDIUM
	 - Required: true

==========================
Retry configurations
==========================
🔘 max.retries

The maximum number of times a failed API request is retried before the task fails. Higher values help the connector ride out longer periods of Dynamics 365 rate limiting.

	 - Type: INT
	 - Default: 5
	 - Importance: MEDIUM
	 - Required: true

==========================
Reporter
==========================
🔘 reporter.error.topic.name

The name of the topic to produce errant records after each unsuccessful API operation. Defaults to 'error-${connector}' if not set. You can provide ``${connector}`` in the value to use it as a placeholder for the logical cluster ID.

	 - Type: STRING
	 - Default: error-${connector}
	 - Importance: LOW
	 - Required: false

	 - Importance: LOW

	 - Default: 
	 - Importance: LOW

🔘 header.converter

	 - Required: false

🔘 value.converter.optional.for.proto2

Whether proto2 optionals are supported. Applicable for Protobuf Converters.

	 - Type: BOOLEAN
	 - Default: 
	 - Importance: LOW
	 - Required: false

🔘 value.converter.reference.subject.name.strategy

Set the subject reference name strategy for value. Valid entries are DefaultReferenceSubjectNameStrategy or QualifiedReferenceSubjectNameStrategy. Note that the subject reference name strategy can be selected only for PROTOBUF format with the default strategy being DefaultReferenceSubjectNameStrategy.

	 - Type: STRING
	 - Default: DefaultReferenceSubjectNameStrategy
	 - Importance: LOW
	 - Required: false

🔘 value.converter.schemas.enable

Include schemas within each of the serialized values. Input messages must contain `schema` and `payload` fields and may not contain additional fields. For plain JSON data, set this to `false`. Applicable for JSON Converter.

	 - Type: BOOLEAN
	 - Default: false
	 - Importance: LOW
	 - Required: false

🔘 value.converter.generate.struct.for.nulls

Whether to generate a struct variable for null values. Applicable for Protobuf Converters.

	 - Type: BOOLEAN
	 - Default: 
	 - Importance: LOW
	 - Required: false

🔘 errors.tolerance

Use this property if you would like to configure the connector's error handling behavior. WARNING: This property should be used with CAUTION for SOURCE CONNECTORS as it may lead to dataloss. If you set this property to 'all', the connector will not fail on errant records, but will instead log them (and send to DLQ for Sink Connectors) and continue processing. If you set this property to 'none', the connector task will fail on errant records.

	 - Type: STRING
	 - Default: none
	 - Importance: LOW
	 - Required: false

🔘 value.converter.ignore.default.for.nullables

When set to true, this property ensures that the corresponding record in Kafka is NULL, instead of showing the default column value. Applicable for AVRO,PROTOBUF and JSON_SR Converters.

	 - Type: BOOLEAN
	 - Default: false
	 - Importance: LOW
	 - Required: false

🔘 producer.override.compression.type

The compression type for all data generated by the producer. Valid values are none, gzip, snappy, lz4, and zstd.

	 - Type: STRING
