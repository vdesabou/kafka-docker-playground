# .NET client (producer/consumer) (using Confluent Cloud)

## Objective

Quickly test the [Confluent .NET Client for Apache Kafka](https://docs.confluent.io/kafka-clients/dotnet/current/overview.html) (NuGet [`Confluent.Kafka`](https://www.nuget.org/packages/Confluent.Kafka), built on librdkafka) and its Avro serializer for Schema Registry ([`Confluent.SchemaRegistry.Serdes.Avro`](https://www.nuget.org/packages/Confluent.SchemaRegistry.Serdes.Avro)) against Confluent Cloud.

## Prerequisites

See [Confluent Cloud examples](https://kafka-docker-playground.io/#/how-to-use?id=%f0%9f%8c%a4%ef%b8%8f-confluent-cloud-examples).

## How to run

```bash
playground run -f start.sh
```

| Script | Description |
| --- | --- |
| `start.sh` | .NET producer and consumer, string and Avro records, running in Docker containers against Confluent Cloud and its Schema Registry |

## What the script does

1. Bootstraps the Confluent Cloud environment and generates `librdkafka.config` (gitignored) from `librdkafka.config.template`: the bootstrap servers and API key of the cluster (`SASL_SSL`, `PLAIN`), and the `schema.registry.*` properties of the Schema Registry client (URL and API key). The client reads one property per line, so any librdkafka property can be added there (`ssl.ca.location` for a custom CA bundle, `debug=broker,protocol`…).
2. Recreates topics `client_dotnet_<TAG>` and `client_dotnet_avro_<TAG>` with `playground topic delete` / `playground topic create`.
3. Builds the `vdesabou/dotnet-ccloud-example-docker` image from the `Dockerfile` (.NET 10, [`Program.cs`](Program.cs), `Confluent.Kafka` and `Confluent.SchemaRegistry.Serdes.Avro` 2.16.0 from [`ClientDotnet.csproj`](ClientDotnet.csproj)).
4. Produces 10 string records (key `alice`, value `{"name":"alice","count":<i>}`) with container `dotnet-ccloud-producer`, then consumes them with container `dotnet-ccloud-consumer` (group `client_dotnet_<TAG>-group`). Both run with the `net.ipv4.tcp_keepalive_time=60` and `net.ipv4.tcp_keepalive_intvl=30` sysctls. The consumer exits with an error if fewer than 10 records arrive within 60 seconds.
5. Same with Avro records (`GenericRecord` of schema `io.confluent.playground.User`): `AvroSerializer` registers the schema under subject `client_dotnet_avro_<TAG>-value`, `AvroDeserializer` reads it back.
6. Checks the Avro records with `playground topic consume --min-expected-messages 10`.
7. On exit, deletes both topics with `playground topic delete`, which also deletes subject `client_dotnet_avro_<TAG>-value`.

The program can also be run by hand once the image is built:

```bash
docker run --rm -v $PWD/librdkafka.config:/tmp/librdkafka.config vdesabou/dotnet-ccloud-example-docker produce client_dotnet_8.4.0 /tmp/librdkafka.config 10
```

## Notes on using Minikube with unsafe sysctls

Run Minikube, with `kubelet.allowed-unsafe-sysctls` to allow unsafe sysctls:

```bash
minikube start --cpus 4 --memory=8G --extra-config="kubelet.allowed-unsafe-sysctls=net.ipv4.tcp_keepalive_time,net.ipv4.tcp_keepalive_intvl"
minikube dashboard
```

Build the Docker image within Minikube (explanations [here](https://dzone.com/articles/running-local-docker-images-in-kubernetes-1)). `Dockerfile-Minikube` bakes in the `librdkafka.config` generated by `start.sh`, and produces to topic `test1` (create it first, Confluent Cloud does not auto-create topics):

```bash
eval $(minikube docker-env)
docker build -t vdesabou/dotnet-ccloud-example-docker -f Dockerfile-Minikube .
```

Create the namespace and run the pod:

```bash
kubectl create namespace dotnet-ccloud-example-docker
kubectl apply -f pod.yml --namespace=dotnet-ccloud-example-docker
```

## Notes on using Minikube with initContainers

Run Minikube:

```bash
minikube start --cpus 4 --memory=8G
minikube dashboard
```

Build the Docker image within Minikube as above (`Dockerfile-Minikube`), then create the namespace and run the pod:

```bash
kubectl create namespace dotnet-ccloud-example-docker
kubectl apply -f pod_initContainers.yml --namespace=dotnet-ccloud-example-docker
```

## Use another client version

Set `CLIENT_VERSION` to build the image with another Confluent.Kafka and Confluent.SchemaRegistry.Serdes.Avro version than the default, the version of `ClientDotnet.csproj`:

```bash
CLIENT_VERSION=2.10.1 playground run -f start.sh
```

Empty or unset: the default version. The client prints its version when it starts, check it in the output. The image is the one of [other/client-dotnet](../../other/client-dotnet/), built with `docker build --build-arg CLIENT_VERSION`. An old version may not support everything the example uses (the Avro serializer API changed over time).
