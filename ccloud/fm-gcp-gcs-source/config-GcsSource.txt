==========================
Which topic(s) do you want to send data to?
==========================
🔘 topic.regex.list

A list of topics along with a regex expression of the files which are to be sent to that topic.  For example: "my-topic:.*" will send all files to "my-topic", while a list containing only the expression "special-topic:.*\.json" will send only files starting with ".json" to "special-topic", and all other files not matching any patterns will be ignored and not sourced. Files that match multiple mappings will be sent to the first topic in the list that maps the file. The ``topic.regex.list`` property matches the full GCS path (for example, ``folder/file.txt``), not just the filename. Not used when Mode is RESTORE_BACKUP_FULL_RECORD.

	 - Type: LIST
	 - Default: 
	 - Importance: HIGH
	 - Required: false

Schema Config
==========================
🔘 schema.context.name

Add a schema context name. A schema context represents an independent scope in Schema Registry. It is a separate sub-schema tied to topics in different Kafka clusters that share the same Schema Registry instance. If not used, the connector uses the default schema configured for Schema Registry in your Confluent Cloud environment.

	 - Type: STRING
	 - Default: default
	 - Importance: MEDIUM
	 - Required: false

Input and output messages
==========================
🔘 input.data.format

Sets the input message format. Valid entries are AVRO, JSON, or BYTES. Note that you need to have Confluent Cloud Schema Registry configured if using a schema-based message format like AVRO.

	 - Type: STRING
	 - Default: 
	 - Importance: HIGH
	 - Required: true

🔘 output.data.format

Set the output Kafka record value format. Valid entries are AVRO, JSON_SR, PROTOBUF, JSON or BYTES. Note that you need to have Confluent Cloud Schema Registry configured if using a schema-based message format like AVRO. Note that the output message format defaults to the value in the Input Message Format field

	 - Type: STRING
	 - Default: ${input.data.format}

🔘 output.key.format

Sets the output Kafka record key format. Valid entries are AVRO, JSON_SR, PROTOBUF, JSON, STRING, or BYTES. Note that you need to have Confluent Cloud Schema Registry configured if using a schema-based key format like AVRO, JSON_SR, and PROTOBUF. BYTES is only allowed when Mode is RESTORE_BACKUP_FULL_RECORD. Note: Output Message Format sets the value converter; this config sets the key converter.

	 - Default: STRING
	 - Importance: HIGH
	 - Required: false

🔘 format.json.schema.enable

When true, expects JSON files with an embedded ``{schema, payload}`` envelope. Only applicable when Input Message Format is JSON. Set true when restoring backups written by the GCS Sink connector with Mode BACKUP_FULL_RECORD in JSON format.

==========================
Mode
==========================
🔘 mode

Sets the connector's operating mode. GENERIC (default) reads records from GCS and produces them to Kafka using the selected input message format. RESTORE_BACKUP_FULL_RECORD reads envelope files written by the GCS Sink connector in BACKUP_FULL_RECORD mode and restores the original Kafka records (key, value, headers, timestamp, partition, Schema Registry metadata), including tombstones.

	 - Type: STRING
	 - Default: GENERIC
	 - Importance: HIGH
	 - Required: false

🔘 restore.topic.prefix

Prefix prepended to the original topic name on restore. For example, prefix "restored-" restores a backup of topic "orders" to "restored-orders". Leave empty to restore to the original topic name. Applies only when Mode is RESTORE_BACKUP_FULL_RECORD.

	 - Type: STRING
	 - Default: 
	 - Importance: MEDIUM
	 - Required: false

🔘 restore.preserve.timestamps

When true, restored records carry the original Kafka producer timestamp captured at backup time. When false (default), restored records use the current wall-clock time. Applies only when Mode is RESTORE_BACKUP_FULL_RECORD. Warning: on topics with time-based retention, restored records whose original timestamp is older than retention.ms may be purged by log retention.

	 - Type: BOOLEAN
	 - Default: false
	 - Importance: MEDIUM
	 - Required: false

==========================
Headers
==========================
🔘 file.metadata.headers.enable

When enabled, each produced Kafka record carries headers describing the source file: ``file.name``, ``file.path``, ``file.last.modified`` (TIMESTAMP), ``file.creation.time`` (TIMESTAMP), and ``file.size`` (LONG). Consumers that don't read these headers are unaffected. Headers whose underlying metadata is unavailable from Google Cloud Storage bucket are omitted. Supported ``header.converter`` values are ``SimpleHeaderConverter`` (default), ``StringConverter``, and ``JsonConverter``.

	 - Type: BOOLEAN
	 - Default: false
	 - Importance: LOW
	 - Required: false
