# 🧠 CLI

`playground` (in `scripts/cli/`) runs the examples and answers support questions in one call: status, diagnosis, logs, configs, schemas, plugin versions, cloud resources… without typing `docker`, `curl` or `kafka-*` commands.

## 🧭 Find the right command

About 300 commands: describe what you want to know, in your own words, and let the CLI pick.

```bash
# the 5 best commands for a question or a symptom, with their usage
playground find-command "connector is slow"
# an example to run
playground find-example "oracle cdc ssl"
# every subcommand and flag of a command, with example output
playground connector --help
```

> [!TIP]
> * The **[🧭 Which command do I need?](/which-command.md)** page maps questions to commands, and raw `docker` / `curl` / `kafka-*` commands to their `playground` equivalent.
> * The **[🍪 Deep dives](/deep-dives.md)** explain one family of commands each: mental model, gotchas, a lab, recipes for support repros.
> * Every command has its own page: use the search box, or the **✨ Command Reference** below.

## 🚜 Setup

> [!TIP]
> The one-line installer does all of this for you (clone, bash 4+, fzf, Confluent CLI, a container engine if you have none, `PATH` and completion), asking before each change: `curl -fsSL https://kafka-docker-playground.io/install.sh | bash`. See [Install in one command](/how-to-use?id=%e2%9a%a1-install-in-one-command).

### 🦶 Setup PATH

Add it to your `PATH` environment variable by adding this in your `~/.bashrc` or `~/.zshrc`:

```bash
export PATH=/path/to/kafka-docker-playground/scripts/cli:$PATH
```

> [!WARNING]
> The bash script generated by [bashly](https://bashly.dev/) runs from any shell, but requires bash 4 or later. On macOS, install it with `brew install bash`.

### ⚡ Setup completion

Completion files are available in `scripts/cli/completions.bash` (bash) and `scripts/cli/completions.zsh` (zsh). They forward each completion request to `playground __complete`, so the `playground` command must be in your `PATH`.

Add the line matching your shell to your `~/.bashrc` or `~/.zshrc`:

```bash
# bash
source /path/to/kafka-docker-playground/scripts/cli/completions.bash
```

```zsh
# zsh
source /path/to/kafka-docker-playground/scripts/cli/completions.zsh
```

### 🪄 VS Code completion

Get [IntelliSense](https://code.visualstudio.com/docs/editor/intellisense) completion for `playground` in the `.sh` files you edit in Visual Studio Code. It uses a slightly modified version of the [Shell Script Command Completion](https://marketplace.visualstudio.com/items?itemName=tetradresearch.vscode-h2o) extension:

![vscode-extension](./images/vscode-extension.gif)

1. Install it:

   ```bash
   playground tools install-vscode-extension
   ```

2. Open a `.sh` file, open the Command Palette (`Ctrl+Shift+P`, or `⌘+⇧+P` on macOS), choose `Shell Completion: Load Command Spec (experimental)`, then type `playground`.

### 🎩 Alfred workflow (macOS)

On macOS, the [Alfred](https://www.alfredapp.com/) workflow puts the most common lookups one keystroke away, without opening a terminal first: find and run examples, pick a connector plugin version or a config key, act on the running connectors, analyze a file selected in Finder.

```bash
playground tools install-alfred-workflow
```

Then type `kdp` in Alfred. Everything it does, its settings and its shortcuts: **[🎩 Alfred workflow](/alfred.md)**.

### 🤖 Using the CLI from AI agents

AI coding agents (Claude Code, GitHub Copilot, Cursor…) drive the playground with the same CLI as you do: there is no MCP server to install. `playground find-command --json` tells them which command answers a question, and commands such as `container logs --errors` or `connector diagnose` give a bounded, non-interactive answer instead of thousands of log lines. The repository `CLAUDE.md` and the [🧭 Which command do I need?](/which-command.md) page give them the full mapping; see [🤖 Claude Code](/claude-code.md) for the skills.

> [!WARNING]
> `playground container logs` follows the logs and never returns: pass `--errors`, `--no-follow` or `--wait-for-log`.

### ⚙️ Config

Your preferences are kept between sessions: change them with [playground config](/playground%20config), or from the ⚙️ CLI preferences entry of the [playground run menu](/how-to-use?id=%e2%9a%99%ef%b8%8f-cli-preferences). `playground config show` prints the current values. The ones people change the most:

| Setting | What |
| --- | --- |
| [container-kill-all-before-run](/playground%20config%20container-kill-all-before-run) | kill every container before each run (`true`), or only stop the previous example (`false`) |
| [editor](/playground%20config%20editor) | the editor every command opens files with (`code`, `vi`, `nano`…) |
| [clipboard](/playground%20config%20clipboard) | copy the connector config to the clipboard (macOS only) |
| [run-log](/playground%20config%20run-log) | write a masked log of each `playground run`, to share it |
| [open-diagnose-report-on-failure](/playground%20config%20open-diagnose-report-on-failure) | open the `connector diagnose` HTML report when a connector fails |
| [account-check-before-run](/playground%20config%20account-check-before-run) | check the account of the provider (AWS, GCP, Salesforce…) before running its example |
